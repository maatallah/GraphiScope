# GS-0001 — Initialisation du système local de suivi

## 1. Objetif

Initialiser un système local de suivi des tâches et de gouvernance des agents, portable, lisible et persistant, sans dépendance cloud ni base de données externe, afin de permettre la reprise fiable du travail d'un agent à un autre.

## 2. Contexte

Le projet GraphiScope a reçu un mandat opérationnel distinct du travail de développement. Le système local de suivi doit servir de référence de gouvernance pour les tâches futures, sans autoriser la phase B ni les développements de produit.

## 3. Périmètre

Inclut :
- inventaire préalable du workspace ;
- vérification du contexte réel ;
- création des fichiers et dossiers autorisés par le mandat ;
- initialisation des règles permanentes ;
- initialisation des registres de projet ;
- documentation de l'état courant ;
- vérification de cohérence de l'initialisation.

## 4. Exclusions

Exclut :
- toute implémentation de GraphiScope ;
- tout développement applicatif ;
- tout prototype fonctionnel ;
- tout lancement de Phase B ;
- toute modification hors du périmètre autorisé ;
- toute opération Git modifiant l'état du dépôt ;
- toute création de document supplémentaire non prévu par le mandat.

## 5. Autorisations

- lecture uniquement du workspace ;
- création des fichiers explicitement autorisés ;
- conservation des fichiers existants ;
- écriture dans le système de suivi local ;
- vérification de cohérence et de traçabilité.

## 6. Étapes

1. inventaire du workspace réel ;
2. lecture des fichiers de contexte et des spécifications ;
3. création de `AGENT_RULES.md` ;
4. création des fichiers de tracking `PROJECT_STATE.md`, `TASKS.md`, `DECISIONS.md`, `EXECUTION_LOG.md` ;
5. création de la fiche `tasks/GS-0001.md` ;
6. vérification de la cohérence des éléments créés ;
7. mise à jour du statut de la tâche en REVIEW ;
8. préparation de la passation pour validation du propriétaire.

## 7. Critères d'acceptation

- tous les fichiers prévus sont présents ;
- les règles sont cohérentes entre elles ;
- les décisions du propriétaire sont distinguées des propositions ;
- l'état initial de GraphiScope est renseigné sans inventer de résultat ;
- aucun fichier extérieur au périmètre autorisé n'a été modifié ;
- aucune opération Git modifiante n'a été effectuée ;
- le système permet à un nouvel agent de comprendre comment reprendre le travail ;
- le statut final de la tâche est `REVIEW` et non `DONE`.

## 8. Résultats et preuves

- fichier `AGENT_RULES.md` créé
- fichier `project-tracking/PROJECT_STATE.md` créé
- fichier `project-tracking/TASKS.md` créé
- fichier `project-tracking/DECISIONS.md` créé
- fichier `project-tracking/EXECUTION_LOG.md` créé
- fichier `project-tracking/tasks/GS-0001.md` créé
- inventaire réel effectué ; aucun dépôt Git détecté ; fichier de contexte conservé

## 9. Problèmes

Aucun problème majeur détecté durant l'initialisation autorisée. Le principal point à surveiller est la validation finale du propriétaire qui reste nécessaire avant toute autre étape.

## 10. Historique

- état initial : non démarré
- validation autorisée : conforme au mandat d'initialisation
- statut actuel : DONE

## 11. Instructions de passation

Un agent reprenant la tâche doit vérifier :
- l'état actuel dans `PROJECT_STATE.md` ;
- la présence et la cohérence des fichiers de tracking ;
- le statut `DONE` de GS-0001 ;
- les éléments du journal d'exécution ;
- l'absence de conflit entre le suivi et l'environnement réel.

Aucun travail de développement ne doit être démarré avant validation explicite du propriétaire.

## 12. Note de revue

Les corrections documentaires ciblées ont consisté à :
- clarifier la gouvernance des tâches et les statuts de transition ;
- distinguer plus nettement proposition, autorisation, exécution et validation ;
- formaliser les règles de concurrence et de passation entre agents ;
- conserver l'historique du journal sans masquer les anomalies de dates ;
- préciser que les horodatages non vérifiés restent déclaratifs, non certifiés ;
- maintenir une distinction claire entre faits vérifiés, hypothèses et décisions du propriétaire.

Limites restantes :
- aucune donnée de production, aucun échantillon réel ni machine cible n'a été introduit dans ce mandat ;
- aucune tâche supplémentaire n'a été autorisée ;
- la Phase B reste non autorisée.

Vérifications réellement effectuées :
- lecture intégrale des six fichiers de suivi ;
- comparaison entre le registre des tâches, l'état du projet et le journal ;
- correction des incohérences de gouvernance et de passation ;
- validation du propriétaire de l'initialisation et de la consolidation du système local de suivi ;
- mise à jour du statut final `DONE` de GS-0001.

Le statut final de GS-0001 est `DONE`, validé par le propriétaire après initialisation et consolidation du système local de suivi.
